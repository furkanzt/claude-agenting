# BDD in this repo

Every observable behaviour of the plugin is a Gherkin scenario in `features/`, bound to a real
test by a citation that a machine checks. See [TDD.md](TDD.md) for how the tests run.

## Glossary (this project's own terms)

| Term | Meaning |
|---|---|
| Workflow | The Claude Code tool that runs a script of `agent()` calls |
| routing | The model and effort an `agent()` call runs with |
| routing guard | `hooks/workflow-routing-guard.py`, a PreToolUse hook on `Workflow` |
| Stage 1 / Stage 2 | Guard stages: Stage 1 denies a call with no `model`/`agentType` or no `effort`; Stage 2 handles plan approval |
| mode | `auto` (decide and run) or `manual` (ask the user, then `--approve`) |
| disposition | `fast`, `balanced` or `quality`: how auto mode leans |
| workflows opt-in | `on`/`off`, whether Workflows run without asking in this chat |
| session record | The per-chat entry in `.agenting-session-state.json` holding those three values |
| `[agenting]` line | The SessionStart context line that carries the record across compaction |
| finish check | `hooks/workflow-finish-check.py`, which reads a finished Workflow's `journal.jsonl` |
| tripwire | `hooks/cache-tripwire.py`, the mid-session model or effort switch cost nudge |
| meter | `scripts/measure-tokenomics.py`, the transcript cost meter |
| clean run | One self-contained task run as its own `claude -p --restricted` process (`scripts/cleanrun.py`) |
| evalkit | `evals/evalkit.py`, the harness that measures model and effort cells |
| row, cell, task, run | A routing-table job type; a model plus an effort; one gradable job; one cell attempting one task once |
| screening / confirmation | The first round of tasks for a row; the later, larger round for a candidate |
| decision bar | The rule in `evals/README.md` that turns pass counts and cost into KEEP, MOVE_TO or NEEDS_CONFIRMATION |
| baseline | The cell the routing table uses today for a row |
| harness version | An integer that, when changed, invalidates every stored run |
| private material | `evals/private/`, gitignored real task material and ground truth |

## Scenario format

- One file per domain in `features/`. A scenario title is unique in its file.
- Gherkin keywords in English; step text in this project's terms, with concrete values
  (`mode auto`, `effort low`, `$0.10 per MTok`), never "some value".
- One behaviour per scenario. The `Then` is a deterministic contract (an exit code, a field of the
  JSON output, a file, a number), not prose.
- Describe behaviour that exists today. Do not describe intentions.

## Citations

Directly above the tags and the `Scenario:` line, one or more comment lines:

```
  # Backed by: tests/test_routing_guard.py::test_name_of_the_test
  Scenario: A call with no effort is denied
```

- `tests/<file>::<function>`: the file must exist and `def <function>` must appear in it. Several
  stacked `# Backed by:` lines are all validated.
- `scripts/quality/<file>::<check_function>`: a live check (none yet).
- File>title citations (`web/x.test.ts > title`) exist in the harness but this repo has no JS tests.

## The ratchet: `@gap @wip`

A scenario with no proof yet is tagged `@gap @wip` and carries `# Backed by: @gap`. A bare `@gap`
fails CI. Bare gaps stay at zero; every `@gap @wip` is cleared before its feature ships. When the
test exists, replace the tag and the `@gap` line with the citation, then regenerate the matrix.

## Generated files

`Scenarios.md` and `docs/scenarios/coverage-matrix.md` are generated by
`python3 scripts/quality/build_coverage_matrix.py`. Do not edit them by hand; the meta-guard fails
on stale totals.

## Honesty note

Nothing executes the Gherkin: there are no step definitions. A scenario is documentation bound to a
test by its citation, and ARMED means only that the cited test exists, which a machine verifies.
Whether that test is sufficient is for an audit to judge (`audit.md` in the tdd-bdd-harness skill).
Hooks are proved by subprocess pipe tests, scripts by CLI tests with `claude` stubbed, and the eval
harness by tests with a stub `claude`; none of them calls a real model.
