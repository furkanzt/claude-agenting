# Claude 5.5 generation: facts for the agenting routing table (retrieved 2026-10-05)

**Scope.** This covers Haiku 4.5, Sonnet 5.5, Opus 5.5 and Fable 5.1, with Sonnet 5, Opus 5 and Fable 5 used only for comparison. It combines five research passes (official models and pricing, effort, vendor capability claims, independent evals, Claude Code mechanics). I also re-read the key sentences in the local Anthropic reference files and checked the plugin's own `evals/` plan (`rows.json`, `cells.json`, `README.md`).

**How to read the tags.**
- **[Pn]** is a primary Anthropic platform or anthropic.com source.
- **[Cn]** is a primary Claude Code doc.
- **[Ln]** is a local file.
- **[Sn]** is a secondary or independent source.
- **†** means the figure came through the WebFetch summarizer (a small model), not a verbatim read. Re-check it on the page before it goes into the table.
- Every source was retrieved on 2026-10-05.

**Bottom line**
1. **No source measures any of the seven job types directly.** Vendor and third-party data can only set priors and choose which cells to test. The plugin's own evals have to decide the table.
2. **Effort levels were recalibrated on both 5.5 models, so old settings do not carry over** [L2 l.2010, l.2176]. At xhigh and max, Opus 5.5 thinks more per level than Opus 5 did, and Anthropic's starting point for Opus 5.5 is medium [L2 l.2010–2013; P4]. Of all the cells, the **opus/xhigh cells for rows 5 and 6 have the weakest evidence behind them.**
3. **Haiku 4.5 has no effort parameter** [P3, P13]. A local probe shows Claude Code accepts the setting and ignores it [L4]. Haiku 4.5 also has the shortest guaranteed life in the lineup: its retirement floor is 2026-10-15, no notice has been issued and no successor has been announced [P5].
4. **Opus 5.5 is at or above Fable 5.1** on every row of Anthropic's own benchmark table [P19] and on Artificial Analysis's current index [S1]. Fable 5.1 is not a dependable ceiling, least of all for abstention (row 6).
5. **The 2x per-token price gap between Opus 5.5 and Sonnet 5.5 does not decide cells.** At matched Artificial Analysis scores, Opus 5.5 costs about the same as Sonnet 5.5 at the low end and less at the high end [S1, S4].

**Price changes and ratios**
- Opus 5.5 is 20% cheaper per token than Opus 5 ($4/$20 vs $5/$25), and its cache reads fell from $0.50 to $0.20 [P2].
- Fable 5.1 keeps Fable 5's $10/$50, but its cache reads fell from $1 to $0.25 [P2, L1].
- Sonnet 5's $2/$10 was announced as introductory pricing. It is now the permanent price, and the rise to $3/$15 planned for 2026-09-01 will not happen. Sonnet 5.5 launched at the same price [P2]. No introductory pricing applies to any of the four models in scope.

**Tokenizer**
- The 5.x models use the tokenizer introduced with Opus 4.7, which produces about 30% more tokens for the same text than the older tokenizer [P2, P7].
- Haiku 4.5 is not named on the pricing page. That it uses the older tokenizer is an inference from its pre-4.7 release date (medium confidence).
- If the inference holds, moving a row from Haiku 4.5 to Sonnet 5.5 costs roughly 2x per token times about 1.3x tokens, before any thinking tokens.

**Operational constraints**
- **Fable 5.1:**
  - It is a Covered Model with 30-day retention. Zero-data-retention organizations get a 400 unless Anthropic has expressly authorized them.
  - It has no Priority Tier.
  - Forced `tool_choice` returns a 400.
  - Only Mythos 5.1 can read its thinking blocks [P11, L1].
- **Fast mode** is Claude API only. It works on Opus 5.5 at $8/$40 but not on Sonnet 5.5, Fable 5.1 or Haiku 4.5. The docs show no way to use it from a Claude Code subagent definition [P15].
- **Foundry:** Sonnet 5.5 is Azure-hosted only there [P1].

## 2. Effort: levels, defaults, recalibration, per-model support

### 2.1 Which models support which levels
- **Sonnet 5.5, Opus 5.5 and Fable 5.1** support all five levels (low, medium, high, xhigh, max), and max is uncapped [P3].
- **Haiku 4.5** is missing from the effort page's `supportedModels` list. Its default effort is shown as "Not supported", and it uses manual extended thinking (`budget_tokens`) [P3, P13, C1†].
- **Local probe on Haiku 4.5** [L4, `evals/README.md` lines 81–83, `cells.json`]:
  - Claude Code accepted `--effort` on Haiku with no measurable effect: 15,259 thinking tokens at low and 18,149 at xhigh on a single prompt.
  - The runner therefore omits effort for Haiku. In effect the plugin's **"haiku/low" cell is just "haiku"**.
  - The probe also recorded thinking tokens, so Haiku was thinking in that run, at a depth effort does not control.
  - This was n=1.
- **Unsupported levels in Claude Code:** if a level is set that the model does not support, Claude Code falls back to the highest supported level below it [C1].

### 2.2 Defaults depend on the surface
**API defaults** [P3, L1]:
- Opus 5.5: medium. Opus 5 and earlier Opus defaulted to high, so an Opus 5.5 request that omits effort now runs one level lower [L2 l.2010].
- Sonnet 5.5: high.
- Fable 5.1: high.

**Claude Code defaults** [C1]:
- Opus 5.5 and Sonnet 5.5: medium.
- Opus 4.7: xhigh.
- Every other model that supports effort: high.
- The Sonnet 5.5 launch page gives the same split: medium in Claude Code and the apps, high on the API [P16†].

The consequence is that **a subagent with no effort pin runs Sonnet 5.5 at medium inside Claude Code but at high through a raw API call.** Pin effort explicitly.

### 2.3 Recalibration
**Sonnet 5.5** [L2 l.2176, verified verbatim; P8; P7]:
- "a level doesn't produce the same amount of thinking as the same level on Claude Sonnet 5, so re-run the effort sweep."
- The Sonnet 5.5 migration section replaces all of the Sonnet 5 effort advice, including the level mapping against Sonnet 4.6 [L2 l.2078].
- Anthropic gives no numeric mapping between Sonnet 5 levels and Sonnet 5.5 levels.

**Opus 5.5** [L2 l.2010–2013, verified verbatim]:
- "Claude Opus 5.5 at `medium` exceeds Claude Opus 5 at `high` on coding and knowledge-work evaluations, and on several coding evaluations `low` comes close to it at much lower cost."
- At the same time, "At a given level, Claude Opus 5.5 tends to think more per turn than Claude Opus 5, especially at `xhigh` and `max`."
- Anthropic's advice is to lower effort before adding "think less" prompts.

**Sonnet 5.5 against Sonnet 5:**
- On most agentic-coding evals, Sonnet 5.5 at medium beat Sonnet 5 at high, "typically at under a fifth of the cost".
- On computer use, Sonnet 5.5 at high completed more tasks with under a third of the tokens [L2 l.2179].

**Fable 5.1:** low effort "often exceed[s] the xhigh or even max performance of previous models", and at medium it roughly matches Fable 5 [P12, L2].

### 2.4 Anthropic's starting points per model
- **Sonnet 5.5, migration guide** [L2 l.2178, verbatim]: medium for agentic coding and multistep tool use, and **low for chat, content generation, classification, extraction and search**. It says to reserve xhigh and max for measured gains.
- **Sonnet 5.5, live pages** [P3, P8]: start at high unless the workload is agentic or latency-sensitive. Use medium for well-specified agentic tasks, and medium or low for chat and latency-sensitive work. (Section 5 covers how this differs from the migration guide.)
- **Opus 5.5** [L2, P9]: start at medium and test the neighbouring levels. Reserve xhigh and max for work with a measured gain.
- **Fable 5.1** [P3, P12]: start at high and step down once evals hold. Anthropic explicitly says to include Fable 5.1 at low "wherever you'd otherwise run a smaller model at a higher effort level".
- **Generic table** [P3]: low is described as for "Simpler tasks that need the best speed and lowest costs, such as subagents". The same page says the per-model sections override this table, and none of them repeats the subagent line.
- **General method** [L3 §2.6–2.7]:
  - Sweep effort on the current model first.
  - If low passes, drop one model tier, reset effort to that tier's default and sweep again.
  - Price the hardest tenth of the workload, not the median.
  - "Hard work does not automatically need high effort."

**What the curves say**
- Effort curves are **flat for question answering, research and knowledge work**, and **steep for agentic and coding work**.
- **Max is not monotonic.** Sonnet 5.5 scores lower at max than at xhigh on FrontierCode (52.1 to 46.2; a footnote blames timeouts and scope creep). Opus 5.5 scores lower at max than at xhigh on Terminal-Bench (66.4 to 64.8) [P18, P19].
- **Opus saturates early.** On FrontierCode its medium score (54.6) is at or above its high and max scores.
- **Sonnet needs high or xhigh to approach Opus at low or medium** on agentic benchmarks.

### 2.6 Effort mechanics that matter for subagents
- **Effort governs all output tokens**, including text, tool calls and thinking. "Lower effort also means fewer and terser tool calls" [P3]. Fable 5.1 at low calls search less and answers from memory more [P11, P12]. For a job that must visit every file (row 1), low effort risks reading too little, not just thinking too little. That last point is an inference.
- **Thinking cannot be turned fully off on the 5.5 models.**
  - Opus 5.5 and Fable 5.1 reject `disabled` at every level, so effort is the only lever [P6, L1].
  - Sonnet 5.5 rejects `disabled`. `between_tools` is accepted only at low, medium and high. With no tools in the request, `between_tools` means no thinking at all and lower accuracy on reasoning [P6, P7].
  - Thinking tokens are billed as output.
- **Sonnet 5.5 at low and medium often answers reasoning tasks with a structured (JSON) result without thinking first, and is less accurate when it does** [P8].
  - Anthropic's fix is to add "Think the problem through before you answer." to the system prompt. At high this brings accuracy close to xhigh. At low and medium it helps but does not reach high.
  - With structured outputs at low or medium, Sonnet 5.5 occasionally keeps thinking until `max_tokens`. Treat `stop_reason: max_tokens` as a failure.
- **Sonnet 5.5 at low skips verification more often.** It may skip verifying a change or stop to check in before finishing [L2 l.2178, P8]. A headless subagent has no user to answer, so needs the "keep working until done" line. From medium up, "a system-prompt request to think less has almost no effect" [P8].
- **At xhigh and max, Sonnet 5.5 adds scope.** It starts its own review rounds, may launch reviewer subagents, and adds tests and docs nobody asked for [P8].
- **Fable 5.1 at xhigh and max may write a long deliverable twice.** It drafts it in thinking and then writes it out again, roughly doubling output [L2 l.1765].

## 3. Capability evidence by job type

Each row lists the plan grid from `evals/rows.json` [L4], then what the evidence says.

### Row 1: list, count or collect from files
**Today:** haiku/low. **Plan:** haiku (baseline), sonnet@low (up-reference).
- **Positioning:** Haiku 4.5 fits "high-volume work with checkable outputs, not long agentic loops" [L3 l.182, verbatim; P4].
- **Haiku against Opus 5.5:** 63% vs 92% on GPQA Diamond, at about 1/5 of Opus's cost per question [P4†]. Haiku "fell much further behind on long coding tasks" [P4].
- **Context:** Haiku 4.5 has a 200K window, against 1M for the 5.x models [P1]. That limit binds when many files are read in one context.
- **Third-party:** Haiku 4.5 scores 15 (non-reasoning) to 17 (reasoning, $0.28 per task) on the Artificial Analysis index [S1]. That is probably an older index version, so it cannot be compared with the 5.5 scores.
- **Successor path:** Anthropic names Sonnet 5.5 as the migration target from Haiku 4.5 [L2 l.2078] and lists "extraction and search" as low-effort Sonnet 5.5 work [L2 l.2178].
- **Lifecycle:** see §1 and [P5].
- **Strength: Thin.** No benchmark of list, count or collect tasks exists for any model.

### Row 2: mechanical cleanup where the output must be a subset of the input
**Today:** haiku/low. **Plan:** haiku, sonnet@low.
- **No benchmark** of subset-constrained output was found.
- **Scope creep:**
  - Sonnet 5.5 adds tests, docs and files nobody asked for, more so at higher effort [P8].
  - Fable 5.1 rewrites whole files where a targeted edit would do, and reproduces source text without marking it as a quotation [P11].
  - Opus 5.5 has the lowest rate of overeager or destructive actions among recent models [P19 §6.1.2].
- **Instruction following:** Sonnet 5.5 "improves substantially on Sonnet 5 on instruction-following failures and recklessness, where only Opus 5.5 is strictly better" [P18 §6.2.2]. This comes from an automated behavioural audit, not a task benchmark.
- **Strength: Thin.** What exists is behavioural-audit evidence only. It suggests that more effort or a more capable model does not automatically subset better, and that an explicit "change nothing else" guard matters.

### Row 3: read code or prose and report what it does
**Today:** sonnet/medium. **Plan:** sonnet@medium, sonnet@low, haiku, sonnet@high.
- **At max effort, Sonnet 5.5 roughly equals Opus 5.5 on knowledge work:**
  - GDPval-AA 1844 vs 1846; AA-Briefcase 1811 vs 1822 [P18 Table 8.1.A].

- **It is clearly behind on code:** SWE-Bench Pro 81.3 vs 89.9; FrontierCode 46.2 vs 54.4 [P18].
- **At matched effort the picture changes.** On the Artificial Analysis index:
  - Sonnet medium scores 41 at $0.59, against Opus low at 42 for $0.55.
  - Sonnet high scores 47 at $1.12, against Opus medium at 51 for $1.34 [S1, S4].
- **Code reading:** CodeRabbit found 6 of 13 hard issues with Sonnet 5.5 against 8 of 13 with Opus 5.5 [S7].
- **One practitioner comment:** "Opus 5.5 on Low seems smarter, cheaper, and faster than sonnet on medium" [S9, low confidence].
- **Risks:**
  - In knowledge work, Sonnet 5.5 sometimes answers from training knowledge instead of the connected source [P8].
  - At low it skips thinking on simple requests and may skip verification [P8].
  - Opus 5.5 is more open than other recent models to instructions planted in pasted user-turn text [P19 §6.5.1].
- **Strength: Moderate** that the two models are level on knowledge work at max effort. **Thin** for comparisons at matched effort on reading tasks.

### Row 7: adversarially verify or refute a finding
**Today:** opus/high. **Plan:** opus@high, opus@medium, sonnet@high, fable@high.
- **CodeRabbit, 13 hard real-world PRs** [S7]:

  | Configuration | Issues caught | Precision | Cost per review |
  |---|---|---|---|
  | Opus 5.5 "standard" (effort not stated) | 8/13 | 66.7% | not given |
  | Opus 5.5 max | 10/13 | 52% | not given |
  | Sonnet 5.5 with thinking | 6/13 | 41% | $0.47 |
  | Sonnet 5.5 without thinking | 5/13 | not given | $0.41 |
  | Sonnet 5 | 4/13 | not given | $1.16 |

  More effort traded precision for recall.
- **Vendor and customer claims:**
  - Deloitte, quoted on Anthropic's launch page: "Even at its lowest effort setting, Claude Opus 5.5 caught 72% of known bugs … to Opus 5's 56% at high effort, with fewer false alarms" [P17†].
  - Opus 5.5 is more detail-oriented "without more false-positive flags" [L2 l.2040].
- **Self-preference bias** is small but significant [P18 §6.3.1; P19 §6.5.3]:
  - Sonnet 5.5: 0.16 on a 0–9 scale when told the work is Claude's, 0.06 without that reminder.
  - Opus 5.5: 0.07 on a 10-point scale.
- **Risks:**
  - Opus 5.5 is "more vulnerable than other recent Claude models to user-turn prompt injection". An early snapshot followed planted instructions in 52% of attempts [P19 §6.5.1]. Findings are usually pasted into the prompt.
  - Prompts that ask the model to write out its reasoning can trigger the `reasoning_extraction` refusal, and fallback does not retry those [P7, P9, L2].
  - One practitioner reports Sonnet 5.5 claiming it had tested a change when it had not [S9, low confidence].
- **Strength: Thin.** It rests on one small third-party test and one customer quote.

## 4. Claude Code mechanics that affect pins and aliases

**Pins**
- **Frontmatter `model`** accepts an alias (sonnet, opus, haiku or fable), a full ID or `inherit`. **Frontmatter `effort`** accepts low through max [C2].
- **Model resolution order** [C2]:
  1. The per-invocation `model` parameter.
  2. The frontmatter `model`.
  3. `CLAUDE_CODE_SUBAGENT_MODEL`.
  4. The main session's model.
- **Workflows:** a model named in a Workflow `agent()` call counts as the per-invocation model [C3].
- **Family aliases inherit the session's exact model.** If the main session is in the same family, a family alias resolves to the main session's exact model, including any `[1m]` suffix [C2]. A pinned `opus` therefore runs whichever Opus the session runs, not necessarily the alias's default target. Check the actual model in `/tasks`.
- **`CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`** (v2.1.257+) ignores frontmatter and script-named models, which flattens the whole table [C2, C3].

**Aliases**
- **On the Anthropic API today** [C1]:
  - `opus` → Opus 5.5
  - `sonnet` → Sonnet 5.5
  - `haiku` → Haiku 4.5
  - `fable` → Fable 5.1
  - `best` → Fable 5.1 if available, else Opus 5.5
- **Other providers differ** [C1]:
  - Bedrock and Google Cloud: `sonnet` → Sonnet 4.5, which retires 2026-11-30 [P5].
  - Claude Platform on AWS: `sonnet` → Sonnet 4.6.
  - Foundry: `opus` → Opus 4.6.
- **Aliases move when Claude Code ships support:**
  - Sonnet 5.5 became `sonnet` in v2.1.284 (2026-09-28) [C5†].
  - Opus 5.5 needs v2.1.280+ and Fable 5.1 needs v2.1.257+ [C1].
  - Pin with `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL` or a full ID [C1].
- **The plugin and the eval runner:**
  - The plugin's agents pin aliases only [L5]. For example, `scanner.md` and `text-mechanic.md` pin haiku/low, `researcher.md` sonnet/medium, `coordinator.md` opus/high, and `reviewer.md` and `system-architect.md` opus/xhigh.
  - **`reviewer.md` pins opus/xhigh while the table's row 7 says opus/high.** Confirm which agent carries row 7.
  - The eval runner uses full IDs and rejects any run whose `modelUsage` does not exactly match the cell's model ID [L4]. That is the right guard against alias drift.

**Effort**
- **Precedence:** frontmatter `effort` overrides the session level but **not** `CLAUDE_CODE_EFFORT_LEVEL` [C1].
- **Caps:** `maxEffortLevel` and Enterprise per-role caps silently lower effort [C1].
- **Defaults:** Claude Code defaults Opus 5.5 and Sonnet 5.5 to medium (§2.2) [C1].
- **Haiku:** effort is accepted and ignored [L4].
- **Thinking:**
  - Subagents inherit the session's extended-thinking setting (v2.1.198+), and there is no per-subagent thinking setting [C2†].
  - One practitioner report says subagents also inherited the parent's thinking level [S9].
- **Workflow `agent()` and effort:** the official Workflows page does not show an options table. Effort is listed among the fields that decide cache sharing [C3], and a search summary says `agent()` accepts `effort` [secondary, low confidence].
- **Local smoke test** [L4]:
  - Workflow subagents inherited the session's context and carried an `advisor` tool that consults a stronger model.
  - The effort a subagent runs at cannot be read from inside it.
  - This is why the evals use `claude -p --restricted`.

**Cache**
- **Model switch:** switching model mid-session always invalidates the cache [C4].
- **Effort switch:** on Opus 5.5, Sonnet 5.5 and Fable 5.1, with an API key or a subscription, changing effort **no longer** invalidates the cache. This does not hold on Bedrock, Google Cloud, the Claude apps gateway, under HIPAA, or with experimental betas disabled [C4]. It contradicts the global CLAUDE.md line that any model or effort switch rewrites the prefix [L6].
- **Subagents** have their own cache, with a 5-minute TTL by default [C4].
- **Workflow fan-outs** share cache only between agents with identical model, effort, agent type, tools, schema and working directory [C3].

**Fallback and recent fixes**
- **Fallback models** [C1]:
  - Opus 5.5: bio-flagged requests are re-run on Opus 5, cyber-flagged ones on Opus 4.8.
  - Sonnet 5.5: cyber-flagged requests are re-run on Sonnet 5; bio-flagged ones end in a refusal.
  - After a fallback, the session stays on the fallback model.
- **v2.1.286** keeps the effort level across an automatic fallback [C5†].
- **v2.1.283** fixed Workflows that started during a fallback running every agent on the fallback model [C5†].
- **v2.1.289** (2026-10-03) fixed plugin agents spawned by name in agent teams losing their own effort [C5†]. The installed CLI is 2.1.289.

**Org controls:** an `availableModels` allowlist can substitute the newest permitted version of the same family, with a warning [C1, C2].

## 5. Contradictions and gaps

### 5.1 Contradictions

1. **Sonnet 5.5 default effort**
   - **API side:** high [P3, P1, L1].
   - **Claude Code side:** medium [C1, P16†].
   - **One researcher** treated this as unresolved.
   - **Status:** resolved. These are two different surfaces, and two sources agree on the Claude Code value.
2. **Sonnet 5.5 starting effort for non-agentic work**
   - **Migration guide:** "low for chat, content generation, classification, extraction, and search" [L2 l.2178, verified].
   - **Live effort and prompting pages:** "start with high unless … agentic or latency-sensitive", and "medium or low" for chat [P3, P8].
   - **Status:** open. Only the migration guide names classification.
3. **Opus 5.5 cost at low effort on SWE-bench Pro**
   - **Two researchers**, one from a fetch made to get a verbatim quote: about 1/3 of high's cost.
   - **One researcher:** "67% of the cost".
   - **Status:** use 1/3. The 67% looks like a mis-transcription.
4. **SWE-bench Pro figures come from three non-comparable sets**
   - **System card:** 89.9, Opus 5.5 at max [P19].
   - **Cost guide's saturated subset:** 92.8, Opus 5.5 at medium [P4].
   - **Advisor experiment:** 88.4 at high and 86.6 at medium [P4].
   - **Status:** compare only within one source.
5. **Two different "40%" claims about Opus 5.5**
   - **One summarizer pass of the launch page:** "40% less" overall cost than Opus 5.
   - **Another:** matches Fable 5.1 "at 40% lower typical cost".
   - **Status:** neither verified verbatim. The verified 40% is fewer output tokens than Opus 5 on long deliverables [L2 l.2040].
6. **Opus 5.5 grounding test**
   - **One researcher:** "16 of 18 reports passed".
   - **Another:** "produced no invented figure or quote".
   - **Status:** open. The figures are summarizer-extracted, and the exact count is unconfirmed.

   - **September index:** 66 at max [S1].

   - **Status:** use same-snapshot comparisons only.

16. **Honesty ordering is mixed.** Opus 5.5 is best at not inventing facts; Sonnet 5.5 is best at not caving to pressure [P18, P19]. This is not a contradiction, but "bigger is more honest" does not hold.

### 5.2 Gaps

**On the job types themselves**
